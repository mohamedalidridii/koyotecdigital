Calvera Assurances

Modernisation de code historique par agents IA

Moderniser un logiciel de 30 ans sans risquer le calcul des primes

En clair

Trois agents IA travaillent ensemble : l’un cartographie le code COBOL et ses règles métier, l’autre le réécrit en Python moderne, le troisième prouve, tests à l’appui, que le nouveau code donne exactement les mêmes résultats.

Le contexte

Le calcul des primes de Calvera Assurances tourne sur un système COBOL écrit dans les années 1990. Les développeurs qui le connaissent partent à la retraite, et chaque évolution réglementaire coûte des semaines. Une réécriture manuelle complète avait été estimée à plusieurs années.

Le défi

  1. 01

    Les règles métier ne sont documentées nulle part ailleurs que dans le code.

  2. 02

    Une seule différence d’arrondi dans le calcul d’une prime touche des milliers de clients.

  3. 03

    Le nouveau code doit être lisible et maintenable, pas une traduction mot à mot.

  4. 04

    L’équipe interne doit garder la main sur chaque changement.

Notre approche

Un agent Analyste parcourt le code avec Tree-sitter, construit le graphe des dépendances et documente chaque règle métier. Un agent Traducteur réécrit les modules un par un en Python idiomatique. Un agent Testeur génère les tests unitaires et rejoue des milliers de contrats réels dans l’ancien et le nouveau système : tant que les sorties diffèrent, le module repart en correction. Chaque module validé arrive en pull request sur GitHub.

La solution, étape par étape

  1. 01

    Un code de 30 ans

    400 000 lignes de COBOL, peu documentées, que plus personne n’ose toucher.

  2. 02

    Cartographié

    L’agent Analyste lit l’arbre syntaxique, relie les modules et documente les règles métier.

  3. 03

    Traduit, module par module

    L’agent Traducteur réécrit chaque module en Python lisible, avec ses commentaires.

  4. 04

    Prouvé par les tests

    L’agent Testeur compare les sorties de l’ancien et du nouveau code sur 10 000 contrats réels.

  5. 05

    Livré par pull request

    Chaque module arrive en revue chez vos développeurs, prêt à être fusionné.

Résultats

  • −65 %de durée de migration estimée
  • 0écart de calcul sur les contrats rejoués
  • 2 400tests unitaires générés
  • 100 %des règles métier documentées

Ce que nous livrons

  • Documentation des règles métier
  • Code Python modernisé, module par module
  • Tests unitaires et banc de comparaison ancien / nouveau
  • Pull requests GitHub prêtes à la revue
